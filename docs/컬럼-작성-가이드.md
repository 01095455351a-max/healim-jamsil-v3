# 원장 컬럼 쓰는 규칙

이 파일은 새 컬럼을 쓸 때 먼저 읽는다. 2026-11-01에 문체와 근거 표기 방식을
새로 정했다. 그 이전 컬럼은 문체 견본으로 삼지 않는다.

공지사항은 규칙이 훨씬 단순하다. 맨 아래 「공지사항」 절을 본다.

**무엇을 쓸지는 `컬럼-계획표.md`에서 고른다.** 이 파일은 「어떻게 쓰는가」만 다룬다.

claude.ai의 **프로젝트**에서 초고를 쓸 때는 이 파일과 `사이트-지도.md`를 지식으로
올린다. 그쪽에는 저장소가 없어 주소를 확인할 수 없다.


## 무엇을 누가 하는가

| | 하는 일 |
|---|---|
| **원장** | 주제 결정 · 의학 내용 검수 · 수치와 참고자료 확인 · 발행 승인 |
| **Claude** | 초안 작성 · 출처 찾기 · 형식 · 중복 확인 · 표현 점검 · 빌드 검증 · 커밋·푸시 |

**의학적 사실을 지어내지 않는다.** 확실하지 않으면 그 문장을 비워 두고 원장에게
묻는다. 이 저장소에는 홈의 학술 논문이 가짜 제목으로 채워져 있던 전례가 있다
(`CLAUDE.md` 참고).

**원장 검수 전에는 발행하지 않는다.** 컬럼은 원장 이름으로 나가고 구조화
데이터에도 저자로 표시된다.


## 문체 — 진료실에서 설명하듯

목표는 「AI가 쓴 티를 감추는 것」이 아니다. 독자가 궁금한 것을 편하게 이해하는
글이다. 의사가 환자에게 차분히 설명하듯 쓴다.

### 가장 먼저 지킬 것

1. **소리 내어 읽어서 실제로 말할 문장만 쓴다.** 진료실에서 환자에게 이렇게
   말하지 않을 문장이면 고친다.
2. **비유로 설명하지 않는다.** 뜻을 한 번 더 풀어야 하는 표현은 쓰지 않는다.
3. **한 문장에는 한 가지 내용만 담는다.**
4. **추상적인 문장 대신 무엇을 하는지 쓴다.** 「종합적으로 살펴야 합니다」가
   아니라 무엇을 살피는지 적는다.

### 실제로 고친 예

| 쓰지 않는다 | 이렇게 쓴다 |
|---|---|
| 어느 쪽의 힘이 더 큰지는 가늠할 수 있고, 먼저 손볼 곳이 달라집니다 | 어느 쪽이 더 크게 작용하는지 살펴보고, 치료를 어디서부터 시작할지 정합니다 |
| 서로를 붙잡는 고리가 됩니다 | 서로를 악화시킵니다 |
| 몸과 머리가 함께 느슨해져야 합니다 | 몸과 마음의 긴장이 풀려야 합니다 |
| 머리는 위험할 수 있는 것을 계속 찾습니다 | 신경이 곤두서서 작은 일에도 쉽게 반응합니다 |
| 지금 더 강하게 돌아가는 쪽부터 다루고 | 더 두드러지는 쪽부터 치료하면서 |
| 마음의 여유도 함께 줄어들 수 있다는 의미로 읽어야 합니다 | 불안이나 우울이 생기기 쉬운 상태가 될 수 있습니다 |
| 위 표의 어느 열에 가까운지 보이기 시작합니다 | 어느 쪽에 가까운지 판단하기 쉬워집니다 |
| 전신의 조절 패턴을 종합적으로 살펴야 합니다 | 맥박·수면·소화 상태를 함께 확인합니다 |

「힘」 「고리」 「손볼 곳」 「돌아가는」 「신호를 보낸다」 「경고등」 「배터리」 같은
말이 나오면 일단 의심한다.

### 그 밖의 문체 규칙

- **존댓말 「~습니다」가 기본이다.** 「~인데요」로 바꾸거나 「사실」 「그렇다면」
  「여기서 중요한 것은」 같은 연결어를 붙인다고 자연스러워지지 않는다.
- **짧은 문장과 긴 문장을 섞는다.** 모든 문단을 같은 길이, 같은 어미로 끝내지 않는다.
  문단은 2~5문장.
- **공감은 담백하게.** 「얼마나 힘드셨을까요」 「몸이 보내는 간절한 신호」 같은
  표현 대신 불편을 정확히 짚는 설명으로 공감한다.
- **같은 말을 반복하지 않는다.** 「개인차가 있습니다」 「전문가와 상담하세요」를
  문단마다 붙이지 않는다. 주의사항은 해당 내용 바로 옆에 한 번 쓴다.
- **전문용어는 처음 나올 때 쉬운 말로 푼다.** 예: 깊은 잠(서파수면)
- **다른 질환 글에 그대로 붙여도 통하는 문장은 지운다.**
  「현대인들은 스트레스로 인해…」 같은 도입이 대표적이다.

### 지어내지 않는 것

- **환자 발언·사례·진료실 일화를 지어내지 않는다.** 「진료하다 보면」
  「제가 만난 환자분들은」은 원장이 실제로 준 내용에만 쓴다.
- 일반적인 상황을 예로 들 때는 실제 사례처럼 읽히지 않게 쓴다.


## 글의 짜임

### 정해진 틀은 없다

「정의 → 원인 → 증상 → 치료 → 생활관리 → FAQ → 마무리」 같은 순서에 끼워 넣지
않는다. 주제를 이해하는 데 필요한 내용만 골라 자연스러운 순서로 잇는다.

다만 아래는 **거의 모든 글에 들어간다.**

| 요소 | 규칙 |
|---|---|
| 도입 | 제목 없이 2~4문장. 독자의 궁금증을 짚고 바로 답의 방향을 말한다. 질환 페이지로 링크를 건다 |
| 근거 문장 | 본문 안에 3~5개 (아래 「근거」 절) |
| 위험 신호 | 증상이 위험할 수 있으면 반드시. 진료를 권하는 문장과 위기 연락처 |
| 한의학 구역 | 대부분의 글에 둔다. 현대의학의 기전과 같은 개념이 아니라는 문장을 함께 쓴다 |
| 참고자료 | 항상 |

### 소제목

- **내용이 드러나게 쓴다.** 「불안하면 잠들기 어려운 이유」처럼 소제목만 읽어도
  무엇을 말하는지 알 수 있어야 한다. AI 검색은 소제목 단위로 답을 찾는다.
- **쓰지 않는 소제목:** 먼저 결론부터 말씀드리면 · 마무리 · 꼭 알아두세요 ·
  한눈에 보기
- 전부 질문형으로 통일하지 않는다. 서술형과 질문형을 섞는다.
- 짧은 설명마다 소제목을 붙이지 않는다. 보통 7~10개.

### 표

비교할 내용은 표로 정리할 수 있다. 「A일까요, B일까요?」 같은 감별형 글에 특히 맞다.

- 열은 3개 이하. 모바일에서 옆으로 밀어 봐야 하므로 칸 안 글은 짧게 쓴다
- **표 안의 내용은 텍스트로 쓴다.** 이미지로 만들면 AI 검색이 읽지 못한다
- 표 바로 뒤에 표를 어떻게 읽을지 한두 문장으로 설명한다

### 자주 묻는 질문

- **본문에서 다루지 않은 질문만 넣는다.** 보탤 것이 없으면 넣지 않는다. 보통 2개
- 본문 내용을 다시 요약하는 질문은 넣지 않는다
- 질환 페이지 FAQ와 같은 질문이면 넣지 않는다

### 마지막

`## 마무리`는 쓰지 않는다. 결론은 본문에서 충분히 말했으면 생략한다.
마지막 구역(보통 FAQ) 뒤에 이 네 줄을 붙이고 참고자료로 넘어간다. 형식을 바꾸지 않는다.

```markdown
관련 컬럼: [제목](/column/파일명/) · [제목](/column/파일명/)

**작성자**: [석선희 원장](/doctors/seok-seonhui/) ｜ 한방신경정신과 전문의
**작성일**: 2026년 11월 1일
**검토일**: 2026년 11월 1일
```

류석균 원장은 `[류석균 원장](/doctors/ryu-seokgyun/) ｜ 임상 22년`을 쓴다.

### 분량

| | |
|---|---|
| 본문 | **3,500 ~ 4,500자** (참고자료·서명 포함). 5,000자를 넘으면 줄인다 |
| 소제목(`##`) | 7 ~ 10개 |

**분량을 채우려고 설명을 늘리지 않는다.** 모자라면 근거 문장이나 표,
실제로 해 볼 수 있는 방법(예: 수면 기록 쓰는 법)을 더한다.

글자 수는 **바이트가 아니라 글자로 센다.** 한글은 UTF-8에서 3바이트라 두 배 넘게
부풀려진다(`wc -m`이 이 환경에서 바이트를 센다).

```
python3 -c "import io,sys;print(len(io.open(sys.argv[1],encoding='utf-8').read().split(chr(45)*3,2)[2]))" content/column/<파일>.md
```


## 근거 — 본문 안에서 밝힌다

AI 검색(구글 AI 개요, ChatGPT, Perplexity 등)은 출처와 수치가 문장 안에 함께 있는
글을 더 많이 인용한다(Aggarwal 등, 2024, KDD — 출처 표기·통계·인용 추가로 노출
약 30~40% 증가, 순위가 낮은 사이트일수록 효과가 컸다). 출처를 글 끝 목록에만 두면
이 효과가 없다.

### 쓰는 방식

한 편에 **3~5개.** 아래 셋 중 하나로 쓴다.

```markdown
건강보험심사평가원 자료에 따르면 2024년 불면증으로 진료를 받은 사람은 …

영국 국민보건서비스(NHS)는 월경이 12개월 동안 없을 때를 폐경으로 봅니다.

미국 캘리포니아대 버클리 연구팀(Ben Simon 등, 2020, Nature Human Behaviour)은 …
```

- 기관: 「기관명 + 내용」을 한 문장에
- 연구: 「소속 연구팀(제1저자 등, 연도, 학술지명)」 다음에 무엇을 했고 무엇이 나왔는지.
  소속을 확인하지 못했으면 「○○ 등(연도, 학술지명)의 연구에서는」으로 쓴다
- 연구 결과를 쓴 뒤에는 **어떻게 읽어야 하는지 한 문장을 붙인다.**
  예: 「불면이 있다고 반드시 불안장애가 생긴다는 뜻은 아닙니다.」

### 수치

- **출처가 확인된 수치는 넣는다.** 금지하는 것은 출처 없는 수치다.
- 수치는 반드시 출처와 **같은 문장**에 둔다.
- 기사에서 본 수치는 원자료(기관 통계, 논문 원문)를 찾아 확인한 뒤 쓴다.
  확인 전이면 「확인 필요」에 올린다.
- 오즈비·상대위험도는 「가능성이 약 ○배 높았다」로 풀어 쓸 수 있다. 원래 지표는
  「확인 필요」에 적어 원장이 검수하게 한다.

### 연구를 쓸 수 있는 곳과 없는 곳

| 쓸 수 있다 | 쓰지 않는다 |
|---|---|
| 유병률·진료 인원 같은 통계 | 치료 효과의 근거 (침·한약·특정 치료가 「효과가 있었다」) |
| 두 증상의 관계, 위험 요인 | 「양약에 비해 ○○」 같은 비교 |
| 기전 설명 (기능·회로 수준) | 진료지침의 치료 권고·권고등급·근거수준 |
| 정의·진단 기준·감별·위험 신호 | 후기·사례 |

치료를 설명하는 대목에서는 연구도 지침도 근거로 삼지 않는다. 환자는 「효과가
입증됐다」로 읽고, 「양약에 비해 한약」을 읽고 복용하던 약을 끊을 수 있다.

**복약 안내는 넣는다.** 약 이야기가 나오는 글에는 「복용 중인 약을 임의로 끊지
말고 처방한 의사와 상의하세요」를 해당 대목에 쓴다.


## 참고자료

본문에서 밝힌 출처는 모두 여기에도 단다. 보통 4~6개.

### 순서

1. 국내 공공기관·진료지침
2. 국내 학술지 논문 (동의신경정신과학회지 등)
3. 해외 학술지 논문
4. 해외 기관

| 국내 | 무엇 |
|---|---|
| 국가한의임상정보포털(한국한의약진흥원) | 한의표준임상진료지침. `nikom.or.kr/nckm/` |
| 대한한방신경정신과학회 | 동의신경정신과학회지 |
| 국가정신건강정보포털(국립정신건강센터) | 질환별 안내. `mentalhealth.go.kr` |
| 국가건강정보포털(질병관리청) | 질환별 안내. `health.kdca.go.kr` |
| 건강보험심사평가원 | 보건의료빅데이터개방시스템. 진료 인원 통계 |

한의표준임상진료지침이 있는 질환 — **불면장애 · 우울증 · 불안장애 · 화병 · 기능성
소화불량 · 자율신경실조증 · ADHD · 과민대장증후군 · 긴장성 두통 · 현훈**

**지침을 인용하기 전에 `지침-요약.md`를 본다.** 지침에서는 정의 · 진단 기준 ·
감별 · 위험 신호 · 의뢰 기준만 가져온다.

### 형식

```markdown
## 참고자료

*아래 자료는 모두 외부 기관이 제공하는 정보로, 클릭하시면 새 사이트로 연결됩니다.*

1. [한국한의약진흥원, 불면장애 한의표준임상진료지침](https://…)
2. [건강보험심사평가원, 보건의료빅데이터개방시스템 — 불면증 진료 인원](https://…)
3. Hertenstein E, Feige B, Gmeiner T, et al. Insomnia as a predictor of mental disorders: a systematic review and meta-analysis. Sleep Medicine Reviews. 2019;43:96-105. [doi:10.1016/…](https://doi.org/10.1016/…)
4. [영국 국민보건서비스(NHS), 폐경 안내](https://…)
```

- 논문: 저자(3명까지, 그 뒤는 et al.) · 제목 · 학술지 · 연도;권:쪽 · DOI 링크
- 기관: 한국어 기관명, 문서 제목. 약자는 괄호에

> **클로드 프로젝트에서 초고를 쓸 때는 주소와 DOI를 채우지 않는다.**
> 기관·문서명 또는 논문 서지만 적고 `[주소 확인 필요]` `[DOI 확인 필요]`를 붙인다.
> 확인은 저장소에서 검색으로 한다.

### 기관 이름

**약자로만 적지 않는다.** 본문과 참고자료 모두 한국어 이름을 앞에, 약자를 괄호에 쓴다.
같은 글에서 두 번째부터는 약자만 써도 된다.

| 약자 | 한국어 이름 |
|---|---|
| NINDS | 미국 국립신경질환뇌졸중연구소 |
| NIMH | 미국 국립정신건강연구원 |
| NHLBI | 미국 국립심폐혈액연구소 |
| CDC | 미국 질병통제예방센터 |
| NHS | 영국 국민보건서비스 |
| NICE | 영국 국립보건의료연구원 (`nice.org.uk/guidance/...`만) |
| WHO | 세계보건기구 |
| Cleveland Clinic | 클리블랜드 클리닉 (약자를 쓰지 않는다) |
| American Heart Association | 미국심장협회 |

표에 없는 기관은 **그 기관이 스스로 쓰는 한국어 이름**을 쓰고, 없으면 영문 그대로.
번역을 지어내지 않는다.

**NICE CKS(`cks.nice.org.uk`)는 쓰지 않는다.** 영국 밖에서는 열리지 않는다.

**주소와 DOI를 기억으로 쓰지 않는다.** 웹 검색으로 실제 존재하는 것을 확인한다.
국내 포털 주소는 `jsessionid`나 긴 꼬리를 떼고 최소 형태로 줄인 뒤 열리는지 확인한다.
확인되지 않으면 그 줄을 비워 두고 원장에게 보고한다.

**2026-09-20 이전에 발행한 18편은 그대로 둔다.** 새 글부터 이 규칙을 따른다.


## 의료광고 — 쓰면 안 되는 표현

의료기관 홈페이지의 글은 광고물이다(의료법 제56조).

| 쓰지 않는다 | 대신 |
|---|---|
| 완치 · 100% · 부작용 없는 · 최고 · 유일 | 쓰지 않는다 |
| 「~때문입니다」로 원인 단정 | 「~가 관여하는 것으로 봅니다」 |
| 특정 뇌 구조를 원인으로 지목 | 기능·회로 수준으로 서술 |
| 「반드시 좋아집니다」 | 「경과를 관찰하며 평가합니다」 |
| 논문·후기를 근거로 치료 효과 단정 | 치료 대목에는 연구를 쓰지 않는다 |
| 불안을 키운 뒤 내원으로 연결 | 위험 신호는 사실대로, 진료 권유는 필요한 곳에만 |
| 질환명·지역명 반복 | 문맥에 필요한 만큼만 |

**부정 맥락은 괜찮다.** 「보장할 수 없습니다」 「단독으로 확진하지 않습니다」는
오히려 필요한 표현이다.

**확인된 사실과 가능성을 구분한다.** 자연스럽게 쓰려고 「~할 수 있습니다」를 모두
지우지 않는다. 한의학적 해석과 현대의학의 기전을 같은 사실처럼 잇지 않는다.


## front matter

```yaml
---
title: "화면에 보이는 제목"
summary: "카드와 검색 결과에 나가는 두세 줄."
date: 2026-11-01
lastmod: 2026-11-01
share: false
authors:
  - seok-seonhui
tags:
  - 불면증
  - 칼럼
title_seo: "검색 제목 17자 이내"
faqs:
  - question: "질문"
    answer: "답"
---
```

| 항목 | 규칙 |
|---|---|
| `title` | 질문형이 기본. 병명이 아니라 증상·상황으로 연다 (계획표 「제목은 환자가 쓰는 말로」) |
| `summary` | 160자 이하. 글이 무엇을 알려 주는지 구체적으로 |
| `date` | **미래 날짜를 쓰지 않는다.** 미래면 화면에 나오지 않는다 |
| `lastmod` | `date`와 같게. 나중에 고치면 그날로 |
| `authors` | `seok-seonhui` 또는 `ryu-seokgyun` |
| `tags` | 질환명 + `칼럼`. 아래 10개만 쓴다 |
| `title_seo` | **17자 이내.** 뒤에 `| 해아림한의원 잠실점`(13자)이 자동으로 붙어 합쳐서 30자다. 넘으면 검색 결과에서 상호가 통째로 잘린다 |
| `faqs` | 본문 「자주 묻는 질문」과 같은 내용. FAQ가 없으면 항목을 뺀다 |

```
자율신경실조증 · 불안장애 · 다한증 · 공황장애 · 불면증
ADHD · 우울장애 · 신경성 질환 · 강박장애 · 틱장애
```

**파일 이름**은 `content/column/<영문-하이픈>.md`. 그대로 주소가 되므로
**올린 뒤에는 바꾸지 않는다.**

```
why-insomnia-becomes-chronic          왜 ~한가
adhd-vs-normal-distractibility        A와 B의 차이
dysautonomia-symptoms                 무엇의 무엇
```


## 쓰기 전에 확인할 것

- **주제가 겹치지 않는가** — `사이트-지도.md`의 컬럼 목록과 대조한다. 겹치는 설명은
  그 글로 링크하고 넘긴다
- 관련 질환 페이지(`content/diseases/`)의 설명과 어긋나지 않는가
- 작성자 — 질환에 맞는 원장으로. **불면증·자율신경실조증은 두 원장이 함께 보므로**
  특정 원장만 보는 것처럼 쓰지 않는다


## 다 쓴 뒤 퇴고

내보내기 전에 한 번 더 고친다. 퇴고 과정은 출력하지 않는다.

- 소리 내어 읽었을 때 어색한 문장, 비유로 된 문장을 고친다
- 다른 질환 글에 그대로 붙여도 통하는 문장은 지우거나 구체화한다
- 같은 뜻을 두 번 말한 곳은 합친다
- 본문 안 근거 문장이 3~5개인지, 모든 수치에 출처가 같은 문장에 있는지 본다
- 다듬는 과정에서 근거·조건·주의사항이 바뀌지 않았는지 확인한다


## 발행 전 점검

원장 검수를 받은 뒤에 한다.

```
hugo                              빌드가 통과하는가
python3 tools/check-mobile.py     모바일 규칙이 빠지지 않았는가
```

- 컬럼 목록 · 홈 · 게시판 · 작성자 페이지에 나오는가 (자동)
- 본문의 내부 링크가 실제 있는 쪽을 가리키는가
- **표가 모바일에서 깨지지 않는가**
- 금칙 표현이 남아 있지 않은가
- 참고자료 주소와 DOI가 전부 확인된 것인가

**질환 페이지 연결은 자동이 아니다.** `content/diseases/<질환>.md`의
`related_columns`에 한 줄 추가하고, 그 질환 페이지 FAQ에 같은 질문이 있으면
답변 끝에 컬럼 링크를 붙인다.

발행은 `master`에 커밋·푸시하면 Cloudflare가 1~2분 안에 반영한다.


## 공지사항

컬럼과 규칙이 다르다.

```yaml
---
title: "추석 연휴 휴진 안내"
_build:
  render: never
summary: "추석 연휴 휴진 일정을 안내드립니다."
date: 2026-09-01
authors:
  - seok-seonhui
  - ryu-seokgyun
tags:
  - 공지
---

안녕하세요, 해아림한의원 잠실점입니다.

(본문)
```

- **`_build: render: never`를 반드시 넣는다.** 공지는 단독 페이지를 만들지 않는다
- 본문은 「안녕하세요, 해아림한의원 잠실점입니다.」로 시작한다
- 참고자료·FAQ·서명은 붙이지 않는다
